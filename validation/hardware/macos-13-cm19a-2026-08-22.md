## Observations

- macOS uses `/var/run/x10-hardware.lock`; Linux uses
  `/run/lock/x10-hardware.lock`.
- macOS exposes USB through IOKit/libusb rather than Linux
  `/dev/bus/usb` nodes and `x10` group permissions.
- The build completed with one macOS-only warning because Apple deprecated
  `daemon()`. Foreground mode, used for this validation and normal container
  supervision, does not call that path.
- BSD `nc` closes short request connections differently from the Linux test
  client. Persistent Python sockets were used for deterministic diagnostics and
  event capture.
- The hotplug callback reports controller removal and arrival, but it does not
  reopen the controller or restart USB transfers. Restart the daemon after a
  disconnect. Until recovery is implemented, use `transfers_ready` rather than
  `usb_connected` alone to determine whether USB communication is usable.

The legacy native text stream still emits a `Tx RF` line when a command is
accepted before USB submission. During disconnection, USB diagnostics and
completion counters are therefore the authoritative transport evidence. This
historical framing behavior was not changed by the recovery fix.
